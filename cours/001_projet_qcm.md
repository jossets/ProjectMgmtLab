# Comprendre le besoin 

## Besoin ou solution

Un besoin décrit comment obtenir un résultat, tandis qu'une solution décrit ce que l'on cherche à obtenir.
- vrai
+ faux


## Chaine des pourquoi

A quoi sert la chaîne des « pourquoi ? » ?
+ remonter du besoin apparent vers sa cause réelle
- estimer la durée d'une tâche
- choisir un outil de planification
- répartir les rôles dans l'équipe


## Bonne exigence

Une bonne exigence doit être :
+ claire
+ mesurable
+ vérifiable
- vague
- formulée avec des mots comme "rapide" ou "simple"


## Definition of Done

La Definition of Done sert notamment à :
+ préciser ce que signifie "terminé" pour l'équipe
- remplacer les tests
- fixer le budget du projet

## Objectif SMART

La méthode SMART signifie :
+ Spécifique, Mesurable, Atteignable, Réaliste, Temporellement défini
- Simple, Motivant, Ambitieux, Rapide, Testé
- Stratégique, Mesuré, Adapté, Rentable, Terminé


## Perimetre

Le "hors-périmètre" est-il important à définir dans un projet ?
+ oui
- non


## Scope creep

Le "scope creep" désigne :
+ l'extension progressive et non maîtrisée du périmètre du projet
- une méthode d'estimation agile
- un type de contrat client


## Business Model Canvas

Le Business Model Canvas permet notamment de :
+ identifier les clients et la proposition de valeur
+ donner une vision globale du fonctionnement économique du projet
- remplacer le cahier des charges
- planifier les tâches du projet


## Qualite cout delai

Modifier un des trois pôles qualité / coût / délai peut avoir un impact sur les deux autres.
+ vrai
- faux

## WBS

Le WBS (Work Breakdown Structure) consiste à :
+ décomposer le projet en éléments de plus en plus petits
- estimer le budget total du projet
- répartir les votes du planning poker


## Livrable

Un livrable est :
+ un résultat concret produit par le projet
- une tâche non terminée
- un risque identifié


## Planning poker

L'objectif principal du Planning Poker est :
+ de construire une estimation collective
- d'obtenir une précision exacte du temps de travail
- de désigner un responsable pour chaque tâche


## CAPEX OPEX

CAPEX et OPEX désignent respectivement :
+ les dépenses d'investissement et les dépenses de fonctionnement
- les risques et les opportunités
- les tâches critiques et les tâches secondaires

## Gantt

Un diagramme de Gantt permet notamment de représenter :
+ les dates de début et de fin des tâches
+ les dépendances et l'avancement
- les rôles de chaque membre de l'équipe
- le détail du budget du projet


## Jalon

Un jalon représente :
+ un événement important plutôt qu'une durée de travail
- une tâche de longue durée
- un risque du projet


## Chemin critique

Une tâche située sur le chemin critique dispose généralement de beaucoup de marge.
- vrai
+ faux

## Etapes de Tuckman

Quel est l'ordre correct des étapes du modèle de Tuckman ?
+ Forming, Storming, Norming, Performing, Adjourning
- Storming, Forming, Performing, Norming, Adjourning
- Norming, Storming, Forming, Adjourning, Performing


## RACI accountable

Dans la matrice RACI, "Accountable" désigne :
+ la personne qui porte la responsabilité finale
- la personne qui réalise le travail
- la personne simplement tenue informée


## RACI roles

La matrice RACI comprend les rôles suivants :
+ Responsible
+ Accountable
+ Consulted
+ Informed
- Reviewer
- Owner

## Avancement

L'avancement d'un projet doit être mesuré à partir de :
+ résultats vérifiables
- l'impression générale de l'équipe
- le nombre d'heures travaillées uniquement


## Risque ou probleme

Quelle est la différence entre un risque et un problème ?
+ un risque est possible, un problème est déjà arrivé
- un risque est toujours plus grave qu'un problème
- il n'y a pas de différence


## Traitement des risques

On peut traiter un risque en :
+ l'évitant
+ le réduisant
+ le transférant
+ l'acceptant
- l'ignorant systématiquement


## Gestion du changement

Un changement de périmètre doit être intégré automatiquement dès qu'il est demandé, sans analyse préalable.
- vrai
+ faux

## Criteres d'acceptation

Les critères d'acceptation doivent être :
+ observables
+ suffisamment précis
- vagues et ouverts à interprétation
- définis uniquement après la livraison


## Plan de tests

Un test réussi apporte une preuve, alors qu'une simple affirmation ne suffit pas.
+ vrai
- faux


## Tests automatises

Les tests doivent idéalement être :
+ automatisés et faciles à rejouer
- manuels et réalisés une seule fois
- optionnels si le délai est court



-- QCM pour le chapitre # Cycle en V / Agile
# Cycle en V / Agile

## Cycle en V

Le cycle en V est particulièrement adapté lorsque :
+ les exigences sont relativement stables et fortement contraintes
- le besoin évolue très fréquemment
- l'équipe ne connaît pas encore les exigences


## Effet tunnel

L'effet tunnel apparaît lorsque :
+ l'équipe travaille longtemps sans fournir de résultat visible
- l'équipe livre très souvent
- le client est trop impliqué dans le projet


## Role agile

En Scrum, qui porte la vision et la priorisation du produit ?
+ le Product Owner
- le Scrum Master
- l'équipe de développement


## Sprint

Un sprint est :
+ une période de durée fixe pour réaliser un ensemble d'éléments du backlog
- une réunion de fin de projet
- un document de cadrage


## Safe framework

SAFe est un framework destiné à :
+ appliquer des principes agiles à des organisations importantes
- remplacer entièrement le rôle du Product Owner
- supprimer les rétrospectives

## Limite WIP

La limitation du WIP (Work In Progress) permet notamment de :
+ éviter de commencer trop de tâches simultanément
- augmenter indéfiniment la charge de l'équipe
- remplacer le besoin de rétrospectives


## Colonnes Kanban

Un tableau Kanban classique comprend généralement des colonnes comme :
+ À faire
+ En cours
+ Terminé
- Facturé
- Archivé

# MVP/Roadmap

## MVP definition

Le MVP (Minimum Viable Product) signifie "produit bâclé".
- vrai
+ faux


## MVP objectif

L'objectif principal d'un MVP est de :
+ vérifier qu'une hypothèse importante est valide auprès de vrais utilisateurs
- livrer la version finale du produit
- réduire au maximum la qualité du code


## Roadmap produit

Une roadmap produit est généralement :
+ plus stratégique et moins détaillée qu'un planning Gantt
- plus détaillée qu'un planning Gantt
- un document figé qui ne doit jamais évoluer



-- QCM pour le chapitre # Amélioration continue
# Amélioration continue 

## PDCA

Le cycle PDCA signifie :
+ Plan, Do, Check, Act
- Plan, Design, Control, Act
- Prepare, Do, Compare, Adapt


## ROTI

Le ROTI (Return On Time Invested) sert à :
+ évaluer si le temps passé en réunion a apporté de la valeur
- calculer le retour sur investissement financier du projet
- mesurer la vitesse de l'équipe en points de story


## Niveau de maturite

Un bon niveau de maturité signifie qu'une organisation doit toujours viser le niveau maximal, quel que soit le contexte.
- vrai
+ faux


## Retrospective

L'objectif principal d'une rétrospective est de :
+ faire progresser la manière dont l'équipe travaille
- trouver un responsable aux problèmes rencontrés
- remplacer la revue de sprint
